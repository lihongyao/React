# 前言

[React Router ↪](https://reactrouter.com/home) 是 React 生态中最流行的路由库之一。它负责将 URL 与页面 UI 关联起来，让单页应用（SPA）在不整页刷新的情况下，拥有类似多页应用的访问体验。

> React Router 是一个多策略路由器。它既可以作为完整的 React 框架使用，也可以只使用最基础的路由能力。

本文基于 **React Router v8**，不再介绍历史版本的写法。

## 三种模式

@See https://reactrouter.com/start/modes

React Router v8 提供三种模式，它们的能力是逐层增加的：

| 模式 | 顶层 API | 提供的能力 | 适合场景 |
| --- | --- | --- | --- |
| **Declarative Mode**（声明模式） | `<BrowserRouter>` | 路由匹配、嵌套路由、导航、URL 状态 | 只需要基础路由，数据层由其他库管理 |
| **Data Mode**（数据模式） | `createBrowserRouter` + `<RouterProvider>` | 包含声明模式的能力，另增 `loader`、`action`、加载状态、错误边界、中间件 | 使用自己的 Vite/打包和后端方案，同时希望路由管理数据流 |
| **Framework Mode**（框架模式） | React Router Vite 插件 | 包含数据模式的能力，另增类型安全的路由模块、自动代码分割、SPA/SSR/预渲染 | 新项目，或需要完整的 React 全栈框架 |

简单理解：

```text
Declarative = 只管“URL 渲染哪个组件”
Data        = Declarative + 读数据 + 写数据 + 加载/错误状态
Framework   = Data + 构建工具 + 约定 + SSR/SSG + 自动代码分割
```

本文使用 **Data Mode**。它既能展示 v8 的核心能力，又不会隐藏 Vite 项目的细节。

> 注意：本文的 Data Mode 项目只需要安装 `react-router`。普通 API 从 `react-router` 导入，`RouterProvider` 这类 DOM 专属 API 从 `react-router/dom` 导入。

# 准备

- React 19.2.7+

## 创建页面组件

先准备几个简单页面，后面会将它们交给路由渲染：

```tsx
export function Home() {
  return <h1>Home</h1>;
}

export function About() {
  return <h1>About</h1>;
}

export function NotFound() {
  return <h1>404 - Page Not Found</h1>;
}
```

## 配置 Data Router

@See https://reactrouter.com/start/data/installation

先在 React 组件树外创建路由：

```tsx
// src/router.tsx
import { createBrowserRouter } from "react-router";
import { Home, About, NotFound } from "./pages";

export const router = createBrowserRouter([
  { path: "/", Component: Home },
  { path: "/about", Component: About },
  { path: "*", Component: NotFound },
]);
```

然后通过 `<RouterProvider>` 渲染：

```tsx
// src/main.tsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { RouterProvider } from "react-router/dom";
import { router } from "./router";
import "./index.css";

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <RouterProvider router={router} />
  </StrictMode>,
);
```

这里有两个重点：

1. `createBrowserRouter` 接收一组**路由对象**，每个对象描述“路径、组件、数据和行为”。
2. `router` 应该在 React 组件树外创建一次，不要把它放进组件或 React state 中反复创建。

# 路由

@See https://reactrouter.com/start/data/routing

## 路由对象

在 Data Mode 中，路由通过 `createBrowserRouter` 的路由对象进行配置。

```tsx
const router = createBrowserRouter([
  {
    path: "/products/:productId",
    Component: ProductDetails,
    loader: productLoader,
    action: productAction,
    ErrorBoundary: ProductErrorBoundary,
  },
]);
```

可以把一个路由对象理解成一张页面说明书：

| 属性 | 作用 |
| --- | --- |
| `path` | 需要匹配的 URL 路径 |
| `Component` | 匹配成功后渲染的组件 |
| `children` | 子路由 |
| `index` | 父路由的默认子路由 |
| `loader` | 组件渲染前读取数据 |
| `action` | 处理数据提交和修改 |
| `ErrorBoundary` | 捕获该路由分支中的错误 |
| `middleware` | 在路由处理前后执行共享逻辑 |
| `lazy` | 按需加载路由实现 |

> `Component: Home` 与 `element: <Home />` 都能定义 UI。Data Mode 中通常使用 `Component`，结构更清楚，也不需要手动创建 React Element。

## 完整结构

下面先看一个相对完整的配置，再逐项拆解：

```tsx
const router = createBrowserRouter([
  {
    path: "/",
    Component: RootLayout,
    ErrorBoundary: RootErrorBoundary,
    children: [
      { index: true, Component: Home },
      { path: "about", Component: About },

      {
        Component: AuthLayout,
        children: [
          { path: "login", Component: Login },
          { path: "register", Component: Register },
        ],
      },

      {
        path: "dashboard",
        Component: DashboardLayout,
        children: [
          { index: true, Component: DashboardHome },
          { path: "settings", Component: Settings },
        ],
      },

      {
        path: "concerts",
        children: [
          { index: true, Component: ConcertsHome },
          { path: "trending", Component: Trending },
          { path: ":city", Component: City },
        ],
      },

      { path: "*", Component: NotFound },
    ],
  },
]);
```

这组配置最终得到：

```text
/                    -> RootLayout > Home
/about               -> RootLayout > About
/login               -> RootLayout > AuthLayout > Login
/register            -> RootLayout > AuthLayout > Register
/dashboard           -> RootLayout > DashboardLayout > DashboardHome
/dashboard/settings  -> RootLayout > DashboardLayout > Settings
/concerts            -> RootLayout > ConcertsHome
/concerts/trending   -> RootLayout > Trending
/concerts/chengdu    -> RootLayout > City
/*                   -> RootLayout > NotFound
```

## 嵌套路由

@See https://reactrouter.com/start/data/routing#nested-routes

子路由会自动继承父路由的路径，并通过父组件中的 `<Outlet />` 渲染。

```tsx
const router = createBrowserRouter([
  {
    path: "/dashboard",
    Component: DashboardLayout,
    children: [
      { index: true, Component: DashboardHome },
      { path: "settings", Component: Settings },
    ],
  },
]);
```

```tsx
import { Outlet } from "react-router";

export function DashboardLayout() {
  return (
    <div>
      <h1>Dashboard</h1>
      <nav>...</nav>

      {/* 这里渲染 DashboardHome 或 Settings */}
      <Outlet />
    </div>
  );
}
```

简单来说：

```text
父路由的 Component = 页面外壳
父路由的 <Outlet /> = 子页面插槽
children            = 可以放进插槽的子页面
```

如果父路由没有 `<Outlet />`，子路由虽然可以匹配成功，但不会出现在页面中。

## 布局路由

@See https://reactrouter.com/start/data/routing#layout-routes

没有 `path`、但有 `Component` 的路由叫作**布局路由**。它会参与 UI 嵌套，但不会向 URL 增加路径段。

```tsx
{
  Component: AuthLayout,
  children: [
    { path: "login", Component: Login },
    { path: "register", Component: Register },
  ],
}
```

匹配结果：

- `/login`：渲染 `AuthLayout > Login`
- `/register`：渲染 `AuthLayout > Register`

URL 中不会出现 `/auth`，因为父路由没有 `path`。

## 路由前缀

@See https://reactrouter.com/start/data/routing#prefix-route

有 `path`、但没有 `Component` 的父路由只负责给子路由添加路径前缀，不会增加一层 UI。

```tsx
{
  path: "concerts",
  children: [
    { index: true, Component: ConcertsHome },
    { path: "trending", Component: Trending },
    { path: ":city", Component: City },
  ],
}
```

这里的 `concerts` 只负责组织路径：

- `/concerts`
- `/concerts/trending`
- `/concerts/:city`

对比记忆：

```text
没有 path      -> 只增加 UI 层级，不增加 URL 层级
没有 Component -> 只增加 URL 层级，不增加 UI 层级
```

## Index 路由

@See https://reactrouter.com/start/data/routing#index-routes

Index 路由是父路由的**默认子路由**。当 URL 正好等于父路由路径时，它会在父级 `<Outlet />` 中渲染。

```tsx
{
  path: "dashboard",
  Component: DashboardLayout,
  children: [
    { index: true, Component: DashboardHome },
    { path: "settings", Component: Settings },
  ],
}
```

- `/dashboard`：渲染 `DashboardHome`
- `/dashboard/settings`：渲染 `Settings`

> Index 路由不能再拥有 `path` 或 `children`。如果它还需要子路由，应将它改成普通布局路由。

## 动态路径段

@See https://reactrouter.com/start/data/routing#dynamic-segments

以 `:` 开头的路径段是动态路径段。匹配到的值会放进 `params`。

```tsx
{
  path: "users/:userId/orders/:orderId",
  Component: OrderDetails,
}
```

当 URL 为 `/users/42/orders/1001` 时：

```tsx
import { useParams } from "react-router";

function OrderDetails() {
  const { userId, orderId } = useParams();

  // userId  -> "42"
  // orderId -> "1001"
}
```

动态参数也会传给 `loader`、`action` 和 `middleware`：

```tsx
async function loader({ params }) {
  return getOrder(params.userId, params.orderId);
}
```

## 可选路径段

@See https://reactrouter.com/start/data/routing#optional-segments

在路径段末尾添加 `?`，可以将该路径段设为可选：

```tsx
{ path: "products/:productId?", Component: Products }
{ path: ":lang?/categories", Component: Categories }
```

匹配结果：

- `/products` 与 `/products/123`
- `/categories` 与 `/zh/categories`

## Splat 路径

@See https://reactrouter.com/start/data/routing#splats

`*` 会匹配剩余的所有路径，常用于文件路径或 404 页面。

```tsx
{ path: "files/*", Component: FileViewer }
```

当 URL 为 `/files/images/avatar.png` 时，可以通过 `params["*"]` 读取剩余部分：

```tsx
function FileViewer() {
  const params = useParams();
  const filePath = params["*"]; // "images/avatar.png"
}
```

全局 404 路由通常写在根路由的最后：

```tsx
{ path: "*", Component: NotFound }
```

> 路由匹配会计算具体程度，而不是简单地从上到下命中第一个结果。例如 `/teams/new` 会优先于 `/teams/:teamId`，因此不需要依赖书写顺序解决静态路径与动态路径的冲突。

# 导航

@See https://reactrouter.com/start/data/navigating

React Router v8 常用的导航方式有五种：

| API | 适用场景 |
| --- | --- |
| `<Link>` | 普通链接 |
| `<NavLink>` | 需要激活或加载状态的导航链接 |
| `<Form>` | 通过表单查询或提交后导航 |
| `redirect` | 在 `loader`、`action`、`middleware` 中跳转 |
| `useNavigate` | 定时跳转、无操作退出等命令式场景 |

## `<Link>`

`<Link>` 用于普通的声明式导航，不会触发整页刷新。

```tsx
import { Link } from "react-router";

export function Header() {
  return (
    <nav>
      <Link to="/">Home</Link>
      <Link to="/about">About</Link>
    </nav>
  );
}
```

只要 UI 的语义是“前往某个页面”，优先使用 `<Link>`，而不是给按钮绑定 `navigate()`。

## `<NavLink>`

`<NavLink>` 是带状态的 `<Link>`，适合导航栏和侧边栏。

```tsx
import { NavLink } from "react-router";

export function Header() {
  return (
    <nav>
      <NavLink to="/" end>
        Home
      </NavLink>

      <NavLink
        to="/dashboard"
        className={({ isActive, isPending }) =>
          isPending ? "text-gray-400" : isActive ? "text-blue-500" : ""
        }
      >
        Dashboard
      </NavLink>
    </nav>
  );
}
```

状态说明：

- `isActive`：当前 URL 已经匹配该链接。
- `isPending`：正在前往该链接，目标路由的 `loader` 还没有完成。
- `isTransitioning`：正在执行 View Transition。
- `end`：要求 URL 在此处结束。否则 `/` 也会匹配所有以 `/` 开头的地址。

`NavLink` 激活时还会自动拥有 `.active` 类，加载中拥有 `.pending` 类。

## `<Form>`

`<Form>` 使用 Web 标准表单模型，并与路由的数据流连接。

GET 表单会将字段写入查询参数并导航：

```tsx
import { Form } from "react-router";

function SearchForm() {
  return (
    <Form action="/search">
      <input name="q" />
      <button type="submit">Search</button>
    </Form>
  );
}
```

输入 `react` 后提交，页面会导航到：

```text
/search?q=react
```

POST 表单会调用目标路由的 `action`：

```tsx
<Form method="post" action="/projects/new">
  <input name="title" />
  <button type="submit">Create</button>
</Form>
```

## `redirect`

在 `loader`、`action` 或 `middleware` 中跳转时，使用 `redirect`：

```tsx
import { redirect } from "react-router";

async function dashboardLoader() {
  const user = await getCurrentUser();

  if (!user) {
    return redirect("/login");
  }

  return { user };
}
```

创建数据后跳转到详情页：

```tsx
async function action({ request }) {
  const formData = await request.formData();
  const project = await createProject(formData);

  return redirect(`/projects/${project.id}`);
}
```

## `useNavigate`

`useNavigate` 用于命令式导航，但应该少用。普通点击跳转使用 `<Link>`，数据处理后的跳转使用 `redirect`。

适合 `useNavigate` 的场景：

- 用户长时间无操作后自动退出。
- 考试倒计时结束后自动交卷并跳转。
- 根据浏览器历史记录前进或后退。

```tsx
import { useNavigate } from "react-router";

function Quiz() {
  const navigate = useNavigate();

  useCountdown(() => {
    navigate("/result", { replace: true });
  });

  return <div>...</div>;
}
```

历史栈操作：

```tsx
navigate(-1); // 后退
navigate(1);  // 前进
```

`replace: true` 会替换当前历史记录，因此用户点击“后退”时不会再次回到被替换的页面。

# URL 参数

@See https://reactrouter.com/start/declarative/url-values

## Route Params

路由参数来自 `:param` 动态路径段，可以在组件中通过 `useParams` 获取。

```tsx
{
  path: "products/:category/:productId",
  Component: ProductDetails,
}
```

```tsx
import { useParams } from "react-router";

function ProductDetails() {
  const { category, productId } = useParams();

  return (
    <div>
      <p>Category: {category}</p>
      <p>Product ID: {productId}</p>
    </div>
  );
}
```

当 URL 为 `/products/electronics/567` 时：

```ts
{
  category: "electronics",
  productId: "567",
}
```

> URL 参数来自用户输入，类型上可能是 `undefined`，使用前应进行校验。

## Search Params

查询参数是 URL 中 `?` 后面的键值对：

```text
/search?q=react&sort=asc
```

通过 `useSearchParams` 读取和更新：

```tsx
import { useSearchParams } from "react-router";

function SearchPage() {
  const [searchParams, setSearchParams] = useSearchParams();

  const query = searchParams.get("q") ?? "";
  const sort = searchParams.get("sort") ?? "asc";

  function changeSort() {
    setSearchParams({ q: query, sort: "desc" });
  }

  return (
    <div>
      <p>Query: {query}</p>
      <p>Sort: {sort}</p>
      <button onClick={changeSort}>Descending</button>
    </div>
  );
}
```

`searchParams` 是 `URLSearchParams` 实例，常用方法包括：

- `get(name)`：获取第一个值。
- `getAll(name)`：获取同名参数的所有值。
- `has(name)`：判断参数是否存在。
- `toString()`：转换成查询字符串。

> 调用 `setSearchParams` 会触发一次导航。不要只修改 `searchParams.set(...)` 而不调用 `setSearchParams`，否则 URL 和页面不会同步更新。

## Location Object

通过 `useLocation` 可以获取当前地址信息：

```tsx
import { useLocation } from "react-router";

function LocationInfo() {
  const location = useLocation();

  return (
    <div>
      <p>pathname: {location.pathname}</p>
      <p>search: {location.search}</p>
      <p>hash: {location.hash}</p>
      <p>state: {JSON.stringify(location.state)}</p>
      <p>key: {location.key}</p>
    </div>
  );
}
```

当 URL 为 `/profile?tab=posts#latest` 时：

```ts
location.pathname; // "/profile"
location.search;   // "?tab=posts"
location.hash;     // "#latest"
```

还可以通过导航传递 `state`：

```tsx
<Link to="/profile" state={{ from: "home" }}>
  Profile
</Link>
```

```tsx
function Profile() {
  const location = useLocation();
  const from = location.state?.from;
}
```

> `location.state` 只存在于浏览器历史记录中，不会显示在 URL 中，也不适合保存刷新后必须保留或需要分享的数据。

# 数据加载

@See https://reactrouter.com/start/data/data-loading

Data Mode 最重要的能力，是把“进入页面前需要的数据”定义在路由上。

```text
匹配 URL -> 执行 loader -> loader 完成 -> 渲染 Component
```

## `loader`

`loader` 在路由组件渲染前执行，返回值可以通过 `useLoaderData` 获取。

```tsx
import {
  data,
  type LoaderFunctionArgs,
  useLoaderData,
} from "react-router";

export async function productLoader({ params }: LoaderFunctionArgs) {
  const product = await getProduct(params.productId);

  if (!product) {
    throw data("Product Not Found", { status: 404 });
  }

  return { product };
}

export function ProductDetails() {
  const { product } = useLoaderData<typeof productLoader>();

  return <h1>{product.name}</h1>;
}
```

将它们注册到同一个路由对象：

```tsx
{
  path: "products/:productId",
  loader: productLoader,
  Component: ProductDetails,
}
```

`loader` 参数中最常用的两个值：

- `params`：动态路径参数。
- `request`：Web 标准 `Request` 对象，可读取 URL、请求头和 `AbortSignal`。

读取查询参数：

```tsx
async function searchLoader({ request }) {
  const url = new URL(request.url);
  const query = url.searchParams.get("q");

  return searchProducts(query);
}
```

> 当用户快速切换页面时，旧导航的 `request.signal` 可能被取消。将它传给 `fetch`，可以避免已经无用的请求继续执行。

```tsx
async function loader({ request }) {
  return fetch("/api/products", { signal: request.signal });
}
```

## `action`

@See https://reactrouter.com/start/data/actions

`action` 负责处理数据修改。`<Form method="post">`、`useSubmit` 和 `fetcher.submit` 都可以调用它。

```tsx
import { redirect, type ActionFunctionArgs } from "react-router";

export async function createProjectAction({ request }: ActionFunctionArgs) {
  const formData = await request.formData();
  const title = formData.get("title");

  const project = await createProject({ title });
  return redirect(`/projects/${project.id}`);
}
```

```tsx
{
  path: "projects/new",
  action: createProjectAction,
  Component: NewProject,
}
```

```tsx
import { Form } from "react-router";

function NewProject() {
  return (
    <Form method="post">
      <input name="title" />
      <button type="submit">Create</button>
    </Form>
  );
}
```

一次提交的完整过程：

```text
提交 Form
  -> 调用当前路由 action
  -> action 修改数据
  -> 自动重新验证页面上的 loader
  -> UI 得到最新数据
```

这意味着通常不需要在 `action` 完成后手动刷新列表。

## `useFetcher`

@See https://reactrouter.com/api/hooks/useFetcher

普通 `<Form>` 提交通常会产生导航。`useFetcher` 适合**读取或修改数据，但不切换页面**的场景，例如收藏、点赞、行内编辑。

```tsx
import { useFetcher } from "react-router";

function FavoriteButton({ productId, isFavorite }) {
  const fetcher = useFetcher();

  return (
    <fetcher.Form method="post" action={`/products/${productId}/favorite`}>
      <button disabled={fetcher.state !== "idle"}>
        {fetcher.state === "submitting"
          ? "Saving..."
          : isFavorite
            ? "Unfavorite"
            : "Favorite"}
      </button>
    </fetcher.Form>
  );
}
```

Fetcher 拥有独立状态：

```text
fetcher.state = "idle" | "loading" | "submitting"
fetcher.data  = loader 或 action 返回的数据
```

快速判断：

```text
提交后需要进入新页面 -> <Form>
提交后留在当前页面   -> <fetcher.Form>
```

# 加载状态

@See https://reactrouter.com/start/data/pending-ui

## 全局加载状态

`useNavigation` 描述当前的全局导航状态。

```tsx
import { Outlet, useNavigation } from "react-router";

function RootLayout() {
  const navigation = useNavigation();
  const isNavigating = Boolean(navigation.location);

  return (
    <div>
      {isNavigating && <GlobalSpinner />}
      <Outlet />
    </div>
  );
}
```

常见状态：

```text
idle       -> 空闲
loading    -> 正在加载目标路由的数据
submitting -> 正在向 action 提交数据
```

## 局部加载状态

- 链接的加载状态：使用 `NavLink` 的 `isPending`。
- Fetcher 的加载状态：使用 `fetcher.state`。
- 普通表单的提交状态：使用 `navigation.formAction` 和 `navigation.state`。

让状态尽量靠近触发操作的位置，用户更容易理解正在发生什么。

# 错误处理

@See https://reactrouter.com/how-to/error-boundary

## `ErrorBoundary`

路由错误边界可以捕获：

- `loader` 中的错误。
- `action` 中的错误。
- 路由组件渲染时的错误。

错误会交给**距离出错路由最近的** `ErrorBoundary`。因此，根路由至少应该提供一个兜底错误边界。

```tsx
import { isRouteErrorResponse, useRouteError } from "react-router";

function RootErrorBoundary() {
  const error = useRouteError();

  if (isRouteErrorResponse(error)) {
    return (
      <div>
        <h1>{error.status}</h1>
        <p>{error.data}</p>
      </div>
    );
  }

  if (error instanceof Error) {
    return (
      <div>
        <h1>Something went wrong</h1>
        <p>{error.message}</p>
      </div>
    );
  }

  return <h1>Unknown Error</h1>;
}
```

```tsx
{
  path: "/",
  Component: RootLayout,
  ErrorBoundary: RootErrorBoundary,
  children: [...],
}
```

## 两种 404

页面不存在与数据不存在是两件事：

**路由不存在**：使用 Splat 路由。

```tsx
{ path: "*", Component: NotFound }
```

**路由存在，但数据不存在**：在 `loader` 中抛出 404。

```tsx
import { data } from "react-router";

async function loader({ params }) {
  const product = await getProduct(params.productId);

  if (!product) {
    throw data("Product Not Found", { status: 404 });
  }

  return { product };
}
```

# 路由懒加载

@See https://reactrouter.com/start/data/route-object#lazy

`lazy` 可以按需加载路由的组件、`loader`、`action` 等内容，减少首屏 JavaScript。

```tsx
{
  path: "dashboard",
  lazy: () => import("./routes/dashboard"),
}
```

对应模块导出路由对象需要的字段：

```tsx
// routes/dashboard.tsx
import { useLoaderData } from "react-router";

export async function loader() {
  return { stats: await getDashboardStats() };
}

export function Component() {
  const { stats } = useLoaderData<typeof loader>();
  return <Dashboard stats={stats} />;
}

export function ErrorBoundary() {
  return <h1>Dashboard failed to load</h1>;
}
```

这里的导出名称必须与路由对象字段一致，例如 `Component`、`loader`、`action`、`ErrorBoundary`。

# 中间件

@See https://reactrouter.com/how-to/middleware

React Router v8 的路由对象可以通过 `middleware` 复用鉴权、日志、耗时统计和数据预处理逻辑。

```tsx
import { redirect } from "react-router";

async function authMiddleware() {
  const user = await getCurrentUser();

  if (!user) {
    throw redirect("/login");
  }
}

const router = createBrowserRouter([
  {
    path: "dashboard",
    middleware: [authMiddleware],
    loader: dashboardLoader,
    Component: Dashboard,
  },
]);
```

中间件按照父路由到子路由的顺序进入，再按照子路由到父路由的顺序退出：

```text
Root middleware start
  Dashboard middleware start
    loader / action
  Dashboard middleware end
Root middleware end
```

需要包裹后续处理时，接收并调用 `next`：

```tsx
async function timingMiddleware({ request }, next) {
  const start = performance.now();

  await next();

  console.log(request.url, performance.now() - start);
}
```

> Data Mode 运行的是浏览器端中间件。Framework Mode 还支持服务端中间件，因此真正依赖服务端 Session、响应头或密钥的鉴权逻辑，应放在服务端完成。

# 导航拦截

@See https://reactrouter.com/how-to/navigation-blocking

表单未保存时，可以使用 `useBlocker` 拦截 SPA 内部导航。

```tsx
import { useState } from "react";
import { useBlocker } from "react-router";

function Editor() {
  const [isDirty, setIsDirty] = useState(false);
  const blocker = useBlocker(isDirty);

  return (
    <div>
      <textarea onChange={() => setIsDirty(true)} />

      {blocker.state === "blocked" && (
        <div>
          <p>内容尚未保存，确定离开吗？</p>
          <button onClick={() => blocker.proceed()}>离开</button>
          <button onClick={() => blocker.reset()}>留下</button>
        </div>
      )}
    </div>
  );
}
```

- `blocker.proceed()`：继续刚才被拦截的导航。
- `blocker.reset()`：取消导航，留在当前页面。

`useBlocker` 只能拦截应用内部导航，不能拦截刷新、关闭标签页或跳往其他网站。后者需要配合 `useBeforeUnload`：

```tsx
import { useBeforeUnload } from "react-router";

function useUnsavedChangesWarning(isDirty: boolean) {
  useBeforeUnload((event) => {
    if (isDirty) {
      event.preventDefault();
      event.returnValue = "";
    }
  });
}
```

浏览器会显示自己的离开确认提示，不能自定义其中的文案。

# 部署注意事项

`createBrowserRouter` 使用正常的 URL，例如 `/dashboard/settings`。用户直接访问或刷新这个地址时，请求会先到达 Web 服务器。

因此，部署 SPA 时需要将未知页面请求重写到 `index.html`：

```text
/assets/*  -> 正常返回静态资源
其他路径   -> 返回 /index.html
```

否则应用内点击链接正常，但刷新子页面可能得到服务器 404。

如果部署环境完全无法配置重写，可以改用 `createHashRouter`：

```tsx
import { createHashRouter } from "react-router";

const router = createHashRouter([...]);
```

它生成的地址类似 `/#/dashboard`。`#` 后面的内容不会发送给服务器，因此不需要服务器重写，但 URL 不如普通路径简洁。

# 总结

React Router v8 的核心并不是“根据 URL 切换组件”这么简单，而是让一个路由同时描述页面的完整生命周期：

```text
path            -> 如何匹配 URL
Component       -> 渲染什么 UI
loader          -> 渲染前读取什么数据
action          -> 如何修改数据
pending state   -> 等待时显示什么
ErrorBoundary   -> 失败时显示什么
middleware      -> 前后执行哪些共享逻辑
```

推荐的理解顺序：

1. 先掌握 `children + Outlet`，理解 URL 与 UI 的嵌套关系。
2. 再掌握 `Link / NavLink / params / searchParams`，完成页面之间的导航。
3. 然后使用 `loader + action + Form`，把页面数据交给路由管理。
4. 最后补上 `useNavigation + ErrorBoundary + lazy + middleware`，形成完整的用户体验。
